# Go 1.26.5 standard library, C port

The formatting that `compiler/protogen` applies to every generated Go file: `go/parser`
(ParseComments), an inserted import block and `go/printer` with
`Config{Mode: TabIndent | UseSpaces, Tabwidth: 8}`. The output depends on the standard library of
the toolchain that built the plugin; the buf.build remote plugin `protocolbuffers/go:v1.36.12` is
built with Go 1.26.5 (later printers format some comments differently), so this is a 1:1 port of
Go 1.26.5 sources (<https://go.dev/dl/go1.26.5.src.tar.gz>; BSD-3-Clause, Copyright The Go Authors).

## Layout

Files mirror Go's `src/` (`go/printer/nodes.go` -> `go/printer/nodes.c`, same function order and
names: `pkg_Name`, methods `pkg_Type_Method`). `go1_26_5.c` is a unity build that includes every
`.c`; all functions are `static` and only the API in `go1_26_5.h` is exported
(`go1_26_5_format_content`, `go1_26_5_decl_idents`, `go1_26_5_forward_decls` (the declaration walk of
protoc-gen-go's public imports), `go1_26_5_quote`, `go1_26_5_format_float` (`strconv.FormatFloat`),
`go1_26_5_is_letter`/`is_digit`/`is_upper` (`unicode`) and `go1_26_5_is_keyword` (`token`)), so
another Go version can be added as a copied directory with a different prefix. Conventions:
`internal.h`.

Ported: `go/token`, `go/scanner`, `go/ast` (types, Pos/End, Inspect), `go/parser` (full grammar),
`go/printer`, `go/doc/comment` (Parse + Printer.Comment), `go/build/constraint` (what the printer
needs), `text/tabwriter`, `strconv` (quoting; `FormatFloat` for `e`/`f`/`g` from
`internal/strconv/decimal.go` and `ftoa.go`, always through the multiprecision path, which yields the
same digits as Go's Ryū fast path), `unicode` predicates (tables generated by
`unicode/mktables.py`, `strconv/mkisprint.py` from the Go sources), `unicode/utf8`, a `strings`
subset. Not ported (marked `not ported` in the code): object resolution, parser trace mode,
`File.GoVersion`, `printer.CommentedNode`, HTML/Markdown/Text output of `go/doc/comment`.

Known deviations: the parser stops with Go's "exceeded max nesting depth" error when it has used
512 KiB of C stack (Go allows 100000 levels of nesting); `math.Exp`/`math.Log` in the printer's
alignment heuristic reproduce Go's amd64 (FMA) assembly bit for bit (assumption: the buf.build
remote plugin runs on amd64; arm64 Go could differ in rare alignment decisions).

## Tests

- `tests/*_test.c`: unit tests (cases from Go's own tests, `tests/testdata/comment` are Go's
  `go/doc/comment` testdata files).
- `testdata/make-corpus.sh [out]` records a corpus into `build/gofmt-corpus` (not committed; needs
  git, patch, go, buf and network access). `cases/`: the former Go implementation of
  protoc-gen-uni is extracted from git revision `c9b2e00` (`UNI_GO_REV` overrides) and patched with
  `testdata/protogen-dump.patch`, so that its `protogen` records every file it formats
  (`UNI_DUMP_GOFMT=<dir>`: input, imports, gofmt output, declaration identifiers); it then runs its
  protocolbuffers/go golden tests and its binary via buf over every `testdata/proto/*` with several
  option sets. `gosrc/`: Go 1.26.5's own sources formatted by the Go 1.26.5 `go/printer` with the
  protogen configuration. `tests/corpus_test.c` (ctest `unit/go1_26_5_corpus`,
  `unit/go1_26_5_corpus_gosrc`, `unit/go1_26_5_corpus_mutate`; skipped without the corpus,
  `-DUNI_GOFMT_CORPUS=<dir>/cases` points elsewhere) compares byte for byte and also feeds mutated
  inputs (`--mutate N seed`) to check that bad input never crashes or hangs.

A new Go version: copy the directory, rename the `go1_26_5` prefix, port the upstream diff of the
files above file by file, regenerate the tables, and rerun the corpus against that Go version.
