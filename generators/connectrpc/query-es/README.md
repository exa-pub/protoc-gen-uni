# connectrpc/query-es

C port of `protoc-gen-connect-query` from
[Connect-Query](https://github.com/connectrpc/connect-query-es) (Apache-2.0):
<https://buf.build/connectrpc/query-es>. No Node.js required. For every service of the files to
generate it writes `<file>-<Service>_connectquery.{ts,js,d.ts}`, which exports the unary methods
of the service for TanStack Query. Generated code imports the service descriptor from the
`<file>_pb` module of [bufbuild/es](../../bufbuild/es/README.md) and needs
`@connectrpc/connect-query`.

```yaml
plugins:
  - local: protoc-gen-uni
    out: gen/es
    opt: [uni-name=connectrpc/query-es, uni-version=v2.3.1, target=ts]
```

## Versions

| version | upstream sources | plugin framework |
|---------|------------------|------------------|
| v2.3.1 | [`packages/protoc-gen-connect-query/src`](https://github.com/connectrpc/connect-query-es/tree/v2.3.1/packages/protoc-gen-connect-query/src) at tag `v2.3.1` (npm `@connectrpc/protoc-gen-connect-query@2.3.1`) | npm `@bufbuild/protoplugin@2.13.0`, `@bufbuild/protobuf@2.13.0` ([`protobuf-es` v2.13.0](https://github.com/bufbuild/protobuf-es/tree/v2.13.0/packages)) |

The buf.build recipe (`plugins/connectrpc/query-es/v2.3.1`) bundles the npm package with esbuild
on Node.js 24; its lockfile pins `@bufbuild/protoplugin` and `@bufbuild/protobuf` 2.13.0. Its
registry configuration adds `import_extension=js` for generated SDKs (not applied by
`buf generate`).

The plugin framework is the port of `@bufbuild/protoplugin` shared with bufbuild/es,
[`pkg/languages/ecmascript/protoplugin`](../../../pkg/languages/ecmascript/protoplugin/protoplugin.h),
which implements v2.17.0; the parts of v2.13.0 that differ are selected with
`PROTOPLUGIN_V2_13_0`:

- no `map_imports` option (an unknown option);
- the values in the preamble (`@generated by ...`, file name, package) are not escaped;
- `import_extension` rewrites the `.js` extension of every import path, also of paths rewritten
  to a package by `rewrite_imports`;
- names are not validated (no `invalid ... name` error);
- comments keep their line breaks (no CRLF/CR/U+2028/U+2029 normalization);
- editions from proto2 up to 2024 (`maximum_edition` 2024; edition 2026 is unknown:
  `unsupported edition unknown (1002) - ...` for a file to generate, `unsupported edition` for a
  dependency);
- every well-known type file is imported from `@bufbuild/protobuf/wkt`.

**Class: direct** ([LAYOUT.md](../../../docs/LAYOUT.md)). protoc-gen-connect-query prints
TypeScript and JavaScript text with `GeneratedFile.print` and runs no formatter: the port prints
the same text. It has generators for all three targets, so protoplugin never transpiles.

## Options

All options of upstream, which are the framework's: `target` (`ts`, `js`, `dts`, joined with
`+`; default `js+dts`), `import_extension`, `js_import_style`, `ts_nocheck`,
`elide_plugin_version`, `keep_empty_files`, `rewrite_imports` and `bootstrap_wkt`. Any other
option fails with `invalid option "<option>"`, like upstream.

## Known differences

- Errors go to `CodeGeneratorResponse.error`. Upstream prints `protoc-gen-connect-query: <error>`
  to stderr and exits with status 1; a request that cannot be parsed fails with
  `protoc-gen-uni: parse request: <error>` on stderr instead.
- Not supported (generation fails with `unsupported by protoc-gen-uni: ...`; protoc and buf never
  produce such a request):
  - a method name starting with a non-ASCII character (upstream lowercases the first UTF-16 code
    unit with `String.prototype.toLowerCase`);
  - a NUL byte in a name of a message, field, oneof, enum, enum value, service or method;
  - the cases listed for [bufbuild/es](../../bufbuild/es/README.md) (NUL bytes in file names,
    packages, type references, ...; known fields with an unexpected wire type).
