# anthropics/buffa

Port of protoc-gen-buffa, the protoc plugin of [buffa](https://github.com/anthropics/buffa)
(zero-copy Protobuf for Rust with editions support), as published on
[buf.build/anthropics/buffa](https://buf.build/anthropics/buffa).

- Upstream: <https://github.com/anthropics/buffa/tree/v0.9.2> (`protoc-gen-buffa/src/main.rs`
  and the `buffa-codegen` crate), Apache-2.0, Copyright Anthropic, PBC.
- The remote plugin is `cargo install protoc-gen-buffa --version 0.9.2 --locked` built with Rust
  1.98.0 (buf's Dockerfile). Locked versions that show in the output: buffa-codegen 0.9.2,
  prettyplease 0.2.37, syn 2.0.114, quote 1.0.44, proc-macro2 1.0.106.

## Usage

```yaml
plugins:
  - local: protoc-gen-uni
    out: gen
    opt: [uni-name=anthropics/buffa, uni-version=v0.9.2, json=true, text=true, views=true, file_per_package=true]
```

| version | status |

## Class

Formatted: every file is a `quote!` token stream that buffa-codegen parses with syn and prints
with prettyplease (`lib.rs` `format_tokens`), under the header
`// @generated by buffa-codegen. DO NOT EDIT.\n// source: <file>\n\n`. The port builds the syn
nodes directly for the prettyplease port (`pkg/languages/rust/formatters/prettyplease`).

## Layout

- `v0.9.2/generator.c`: `main.rs` (option parsing with its error texts, the response with
  `supported_features` = PROTO3_OPTIONAL | SUPPORTS_EDITIONS, editions PROTO2..2024).
- `pkg/languages/rust/buffa-codegen`: the buffa-codegen 0.9.2 library (shared with
  connectrpc/rust, which uses buffa-codegen 0.9.1).
- `pkg/languages/rust/proc-macro2`: literal token text (`Literal::string`, suffixed numbers, Rust
  float Display).

## Golden tests

`testdata/checksums/anthropics/buffa/v0.9.2.buf.gen.yaml`: every input (including `rust-long`:
long names, defaults and comments for the 100-column prettyplease layout) with eight option groups:
`default`; `bsr` (json, text, views, file_per_package); `lean` (no views, no unknown fields, no
setters, no register fn); `reflect` (vtable reflection, file_per_package, idiomatic imports and
field names, unbox_oneof); `gated` (json, text, vtable reflection behind `gate_impls`, arbitrary,
`open_enums_in=.`, `type_name_prefix`); `bridge` (bridge reflection, shared descriptor pool, no
views, strict UTF-8 mapping, MessageSet, a WKT `extern_path`); `lazy` (lazy views, json);
`lazy-lean` (lazy views without unknown fields, behind `gate_impls`, `open_enums_in=.`,
file_per_package, idiomatic imports).

## Options

All options of `parse_config` are parsed with upstream's error texts: `views`, `lazy_views`,
`unknown_fields`, `json`, `text`, `arbitrary`, `gate_impls`, `{json,views,text,reflect}_feature`,
`allow_message_set`, `strict_utf8` / `strict_utf8_mapping`, `register_types`, `with_setters`,
`reflection`, `reflect_mode`, `shared_descriptor_pool`, `file_per_package`, `idiomatic_imports`,
`idiomatic_field_names`, `unbox_oneof`, `unbox_oneof_in`, `type_name_prefix`,
`override_feature_in`, `open_enums_in`, `exclude_package`, `extern_path`, `mod_file` (always an
error) and `element_memory_limit`.

## Unsupported

Nothing: every option the plugin accepts is ported.

## Known differences

- Request decoding: pkg/pb parses the request; buffa's own decode errors (invalid UTF-8 in
  strings, wire types that do not match the descriptor field) are not reproduced. The
  element-memory budget is checked like buffa does (`bc_decode_request`).
- Warnings (stderr upstream: unmatched overrides, excluded references, suppressed aliases or
  accessors) are not printed.
- `BUFFA_ELEMENT_MEMORY_LIMIT` (environment) is not read, as for the remote plugin, which runs
  without it: the budget is the `element_memory_limit` option or 1 GiB.
- Non-ASCII text in string literals: `char::escape_debug` uses approximate Unicode ranges instead
  of Rust's printable and grapheme-extend tables (`pkg/languages/rust/std`).
